# 법적 점검표 — 실사용 전 확인할 것

2026-11-09. 코드 기준 커밋 `1f9416f` 이후. 이 문서는 법률 자문이 아니다. 각 항목의 "현재 상태"는 코드를 직접 확인한 사실이고, "해석"은 일반적으로 알려진 기준을 적은 것이라 **변호사 검토로 확정**해야 한다. 아래 "변호사에게 물을 것"이 그 목록이다.

## 앱이 실제로 하는 것 (코드로 확인)

- 건강 정보(혈액형·알레르기·약·문진·진료기록)는 모두 기기 `localStorage`에만 저장된다. 서버 저장소가 없다.
- 기기 밖으로 나가는 요청은 세 가지뿐이다.
  1. 병원 목록 JSON(같은 서버, 개인정보 없음) — `src/booking/hospitals.ts`
  2. 결제 승인 `POST /api/confirm`(주문번호·결제키·금액) → 서버가 토스페이먼츠로 전달 — `src/subscribe/SubscribeScreen.tsx`, `api/confirm.ts`
  3. Vercel Analytics 페이지뷰 + 의료비 체커 이벤트 5종(브라우저별 무작위 식별자 포함, 건강 정보 없음) — `src/checker/analytics.ts`
- 위치 정보를 쓰지 않는다. 지도는 외부 지도 사이트를 새 탭으로 열 뿐이다(`nearbyMap.ts`).
- 푸시 알림·문자·이메일을 보내지 않는다. 연락처(이메일·전화)를 서버로 수집하지 않는다.
- 주민등록번호·증명서 원본·사진을 저장하지 않는다(가린 문서확인번호 일부만).
- 의사 화면 QR 검증은 환자가 직접 보여준 선택 공개(SD-JWT) 자료만 읽는다.

## 수익모델에 대한 함의

- **병원에서 추천 대가를 받는 모델은 하지 않는다**(의료법 27조 3항). 예약당 수수료, 노출 광고비, 환자 할인 쿠폰 모두 위험하다.
- 가능한 쪽: 환자 구독(지금 월 3,900원), 병원용 문진 도구 월 이용료(병원이 자기 환자용 도구로 쓰는 SaaS — 환자를 특정 병원으로 보내는 게 아니므로 유인과 다르다고 보이나 **변호사 확인 필요**), 응급 QR 스티커·카드 판매.
- 라벨 데이터 판매는 가명처리·심의 없이는 불가.

## 변호사에게 물을 것

1. 증상 정리 → 진료과 안내 → 위험 조합 시 119 안내(병명 없음)가 의료기기 소프트웨어 또는 의료행위에 해당하지 않는다고 볼 수 있는가? 어떤 문구가 선을 넘는가?
2. 병원용 "문진 도구 월 이용료" 모델이 의료법 27조 3항(환자 유인·알선)에 걸리지 않으려면 어떤 조건이 필요한가? 병원이 환자에게 우리 앱을 권하는 것은?
3. 의사가 우리 화면에 소견·처방·진료비를 입력하는 기능을 실사용으로 열면 전자의무기록·처방전 교부 규정과 충돌하는가? 환자 기기 보관용 "사본"으로만 한정하면 되는가?
4. 보호자가 부모의 건강정보를 대신 등록할 때 체크박스 동의 확인으로 충분한가, 본인 인증이나 서면 동의가 필요한가? 가족관계증명서 문서확인번호 일부 보관은 문제없는가?
5. 서버 없이 기기에만 저장하는 구조에서 우리는 "개인정보처리자"인가? 처리방침·보호책임자 의무가 어디까지 적용되는가?
6. Vercel Analytics의 브라우저별 무작위 식별자는 개인정보 또는 행태정보로 보아 별도 고지·거부 수단이 필요한가?
7. 월 3,900원 1회 결제(자동갱신 없음)에서 청약철회 7일 적용 범위와, 결제 직후 프리미엄 기능을 쓴 경우의 환불 기준은?
8. 응급 잠금화면 QR(혈액형·알레르기·연락처를 누구나 읽게)을 환자 본인이 선택해 설정할 때 우리 책임 범위와 필요한 고지는?
9. 라벨링 데이터(증상 문장·의사 확인)를 추후 연구·개선 목적으로 서버에 모으려면 어떤 동의·가명처리가 필요한가?
10. 의료진이 환자 QR을 검증해 보는 의사 화면에 대해 의료기관 쪽에 필요한 절차(개인정보 처리위탁 등)가 있는가?
