# 병원 시연 대본 — 5분

2026-11-09 기준(커밋 `4ca8ade` 이후). 대상: 원장·간호사·접수 담당. 준비물: 노트북(의사 화면) + 내 폰(환자 화면). 둘 다 같은 주소를 연다. 인터넷이 되는 곳이면 배포 주소, 안 되면 노트북 하나로 화면을 오가며 보여준다.

## 한 문장

> "환자가 말로 설명하지 못하는 증상을 눌러서 정리해 오면, 진료 전에 문진표처럼 받아 보실 수 있습니다. 진단을 대신하는 게 아니라 문진 시간을 줄이는 도구입니다."

## 시작 전 준비 (2분, 병원 들어가기 전에)

1. 노트북에서 `/doctor` 를 연다. 대기열 아래 **"시연 환자 불러오기"** 를 누른다 → 오늘 날짜 예약 4명(박영희·이준호·최민서·김복순)이 "시연" 배지와 함께 들어온다.
2. 폰에서 앱을 연다. 첫 실행이면 온보딩 3장 → 마지막 장에서 동의 2개 체크 → 시작하기.
3. 폰은 홈(`/wallet`)에 둔다.

왜 미리 넣나: 병원에서는 환자 폰과 의사 노트북이 저장소를 공유하지 않는다. 그대로 열면 대기열이 비어 보인다. 시연 환자는 실제 문진 엔진으로 만든 데이터라 카드 내용이 실제 흐름과 같다.

## 흐름 (5분)

### 1. 환자: 말로 증상 정리 (1분 30초) — 폰

- 홈 → **예약** 카드(시연) → "어디가 아프세요?"에 환자가 하는 말 그대로 친다. 예: **"머리가 아프고 다리도 근데 좀 아프네 그리고 어깨가 왜 뻐근하지"**
- 아래 대화 카드에서 머리·목·어깨·다리·발이 **미리 선택**돼 있다 → **다음**
- "이 중에 가장 불편한 곳은 어디예요?" → **머리**
- 머리 느낌: **욱신욱신(맥박이 뛰듯 쿵쿵)** → 목·어깨: **뻐근·결림** → 다리·발: **잘 모르겠어요**
- 언제부터: **1~3일 전** → 얼마나: **보통** → 심해지는 때: **움직일 때** → 다음 → 같이 있는 증상: **없음** → 다음
- 정리된 문장이 뜬다: "1~3일 전부터 머리가 욱신욱신 아프고, 목·어깨가 뻐근하고 결리고, 다리·발이 불편해요. 가장 불편한 곳은 머리예요. …"
- 말할 것: "표현을 모르는 분도 비유를 고르기만 하면 됩니다. 병명은 절대 말하지 않습니다."

### 2. 환자: 진료과·병원·시간 (40초) — 폰

- 추천 이유가 보인다: "여러 곳이 함께 아파서, 먼저 전체를 보는 가정의학과를 추천해요. 가장 불편한 머리는 신경과에서도 볼 수 있어요." → **가정의학과 예약 →**
- 병원 선택: 상급종합 14곳이 바로, 아래 **구 선택**(예: 강남구) → 그 구에서 가정의학과가 있는 곳만 나온다(심평원 공공데이터, 서울 19,929곳). 이 병원이 서울이면 **구를 골라 이 병원을 찾아 보여준다.**
- 시간: **오늘 15:30** → **예약하기 (시연)** → 완료 카드.
- 말할 것: "예약 자체는 아직 병원 시스템과 연결되지 않은 시연입니다. 연동되면 이 자리에 실제 예약이 들어옵니다."

### 3. 의사: 대기열과 문진 카드 (1분 30초) — 노트북

- `/doctor` 를 새로고침한다(같은 기기면 방금 예약한 환자가 **15:30 김단유**로 대기열에 보인다. 다른 기기면 시연 환자 4명으로 진행).
- **박영희 → 문진** 버튼: 가장 불편한 곳, 부위별 느낌과 비유, 시작, 아픈 정도 "5/10 · 일상이 불편한 정도", 심해지는 때, **없다고 답한 증상**(열·구토·어지러움·저림·숨참), 환자가 쓴 말 "진통제를 먹어도 그대로예요".
- 맨 아래 작은 글씨: "환자가 받은 안내: 가정의학과 · 신경과 (규칙 기반 진료과 안내, 진단 아님)".
- 말할 것: "환자가 고른 답과 직접 쓴 말을 그대로 보여드립니다. 저희 해석은 섞지 않습니다. '없다고 답한 증상'까지 보이니 다시 묻지 않으셔도 됩니다."
- **김복순 → 문진**: 카드 맨 위에 "환자 화면에 '119' 안내가 표시됐어요" 알림. 말할 것: "가슴 통증에 숨참이 같이 있으면 예약보다 119를 먼저 안내합니다. 병명은 말하지 않습니다."

### 4. 의사: 진료 완료 (40초) — 노트북

- 김단유(또는 박영희) 카드 아래 **진료 완료 입력**: 소견 한 줄, 처방(약 이름·용법·일수 → **처방 추가**), 진료비 **18500** → **진료 완료 → 환자 수납으로 (시연)**
- 대기열에서 빠지고 "김단유님 진료를 마쳤어요 — 18,500원 수납대기로 환자 수납 화면에 떴어요".
- 말할 것: "이 입력은 EMR이 아니라 시연입니다. 실제로는 EMR 연동이나 환자 보관용 사본으로만 갑니다."

### 5. 환자: 수납 (30초) — 폰(같은 기기일 때)

- 홈 → 미납 진료비 → 방금 진료가 **수납대기**로, 소견·처방·"수납하기 · 18,500원 (시연)".
- 말할 것: "환자는 진료실을 나오면서 소견과 처방을 폰에서 보고 수납합니다. 결제·수납 연동은 시연입니다."

## 의사·간호사에게 물을 것 (3개)

1. "지금 문진표 받고 정리하는 데 환자 한 분당 몇 분 걸리세요? 이 카드가 오면 몇 분이 줄 것 같으세요?"
2. "이 카드에서 **없어도 되는 항목**과 **꼭 더 있어야 하는 항목**은 뭔가요?" (예: 기저질환·복용약·알레르기를 문진에 넣을지)
3. "환자에게 이 앱을 권하신다면 어떤 식으로 권하시겠어요? 접수 데스크 안내문, 예약 문자 링크, 대기실 QR 중에."

## 측정할 것 (파일럿 1~3곳)

- 환자 1명당 문진 정리 시간(분) — 전/후
- 문진 카드가 "쓸모 있었다"고 의사가 답한 비율(⑤ 의사 확인 버튼이 생기면 자동 집계)
- 추천 진료과가 맞았다고 의사가 표시한 비율
- 환자가 대화 문진을 끝까지 마친 비율, 평균 소요 시간

## 솔직히 말할 한계

- 병원 예약 시스템·EMR·전자처방전·수납 연동이 없다. "시연" 표시 기능은 모두 흐름 미리보기다.
- 환자 폰과 의사 노트북이 같은 기기 저장소를 쓰는 구조라, 다른 기기 간에는 서버가 생겨야 넘어간다.
- 진료과 추천은 규칙 기반이고 정확도를 검증한 적이 없다. 의사 확인 데이터가 쌓인 뒤 숫자로 말한다.
- 병원 목록은 2026-09-30 기준 공공데이터라 진료시간·휴무는 없다.
- 약관·개인정보처리방침은 변호사 검토 전 초안이다.

## 막혔을 때

- 대기열이 비어 있다 → "시연 환자 불러오기". 시연 환자를 지우려면 같은 버튼("시연 환자 지우기").
- 폰에서 온보딩이 다시 뜬다 → 동의 2개 체크 후 시작하기(약관 버전이 바뀌면 다시 묻는 게 정상).
- 의사 화면이 흰 화면 → 새로고침(배포 직후 한 번 자동 새로고침되는 게 정상).
- 병원이 서울 밖이다 → 상급종합 목록에서 아무 곳이나 골라 진행하고, 지역 확대는 데이터 추가로 된다고 말한다.
