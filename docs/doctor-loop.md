# 의사 화면 개발 루프 — 진행 기록

의사 화면(`/doctor`)은 지금까지 "응급 신원 QR 검증" 한 가지만 했다. 진료 흐름(대기열 → 문진 확인 → 진료 기록·처방 → 수납 요청)을 붙여 환자 지갑과 양방향으로 잇는다.

원칙
- 실제 EMR·병원 예약·전자처방전 연동이 없다. 화면마다 "시연"으로 표기한다.
- 환자 화면과 의사 화면은 같은 기기 저장소(localStorage)를 함께 쓰는 시연이다. 화면에 그렇게 밝힌다.
- 주민번호·서류 원본은 저장하지 않는다.
- 기능마다 실패하는 테스트를 먼저 쓴다. 빌드와 전체 테스트가 통과해야 커밋한다.

## 서비스 핵심 (2026-11-09 사용자 방향)

> 어디가 아픈지 대화하면서 진료 예약을 하는 것이 서비스의 핵심이다. 환자 대부분이 자신의 아픔을 말로 잘 설명하지 못한다.

그래서 환자 쪽 **대화형 문진**을 의사 화면보다 먼저 만든다. 문진 결과가 의사 화면의 사전 문진 카드로 그대로 넘어가므로 두 화면이 한 흐름이 된다.

대화형 문진 원칙
- 진단하지 않는다. 증상을 정리해서 의사에게 전달하는 "말로 하는 문진표"다. 병명 추정 문구를 쓰지 않는다(의료기기 소프트웨어 규제 영역을 피한다).
- 서버·LLM 없이 규칙 기반으로 기기 안에서 동작한다. 한 번에 한 질문, 누르는 답 + 자유 입력.
- 말로 설명하기 어려운 사람을 위해 통증 느낌을 쉬운 비유로 고르게 한다(예: 욱신욱신 = 맥박이 뛰듯, 찌릿찌릿 = 전기가 오듯).
- 위험 신호가 나오면 예약 대신 119·응급실 안내를 먼저 띄운다.
- 진료과 추천은 지금처럼 규칙 기반이고, 고른 부위 기준으로 정한다.

### 병원 시연 목표 (2026-11-09 사용자 방향: "지금 바로 병원 가서 써보실래요?")

- 보여줄 것은 기능 목록이 아니라 **한 환자의 5분 흐름**이다: 환자가 말로 증상 정리 → 예약 → 의사 대기열에 문진 카드 → 진료 완료 → 환자 수납.
- 의사·간호사에게 파는 가치는 "문진 시간이 줄고, 환자 말이 정리돼 들어온다"는 것 하나다. 진단 보조·AI는 말하지 않는다.
- 실제 구매자는 의사 개인이 아니라 접수·간호 인력과 원장(병원 운영)이다. 의사 화면은 접수 데스크 화면이기도 해야 한다.
- 시연에서 솔직히 말할 것: EMR·예약 시스템 연동 전이고, 환자 폰과 의사 화면이 같은 기기 저장소를 쓰는 시연이다.
- 돈은 환자 구독(월 3,900원)보다 병원 월 구독(접수·문진 디지털화)이 먼저 현실적이다. 숫자는 파일럿 1~3곳의 측정치(문진 시간·노쇼)로 만든다.

### 의사 화면 원칙 — "인터넷에서 답을 받아 온 환자"가 되지 않게 (2026-11-09 사용자 질문 반영)

의사들이 싫어하는 건 환자가 인터넷·AI에서 병명을 받아 와 그걸 전제로 말하는 상황이다. 우리는 환자에게 답을 주는 서비스가 아니라 의사에게 문진을 정리해 주는 서비스로 만든다.

- 환자에게 병명을 보여주지 않는다(문진 원칙과 같음). 환자는 "어느 과로 가면 되는지"까지만 안내받는다.
- 의사 카드에는 환자가 고른 답과 환자가 직접 쓴 말을 그대로 보여준다. 우리 해석을 섞지 않는다.
- 우리 추천 진료과는 "환자가 받은 안내"로 작게만 표시한다. 진단·판단은 의사 몫이다.
- "없다고 답한 증상"도 따로 보여준다(의사가 다시 묻지 않아도 되게).
- 의사가 추천이 맞았는지 누를 수 있게 한다(⑤). 의사가 규칙을 바로잡는 쪽에 서게 한다.
- 지금은 정확도를 주장하지 않는다. ⑤ 데이터가 쌓인 뒤에 숫자로 말한다.

### A3 규칙 — 증상이 여러 개 한꺼번에 있을 때 (2026-11-09 사용자 질문 반영)

순서대로 본다.

1. **위험 조합을 가장 먼저 본다.** 하나씩은 흔해도 같이 나오면 위험한 조합이 있다. 해당하면 진료과 추천 대신 119·응급실 안내를 먼저 띄운다(예약도 할 수는 있게 둔다).
   - 가슴 + (숨이 참 · 팔/어깨 쪽 통증 · 아주 심함) → 119
   - 머리 + 저림·감각 이상 → 119(갑자기 생긴 마비·저림)
   - 머리 + 열 + 목·어깨 → 응급실(목이 뻣뻣한 고열 두통)
   - 아픈 정도 "아주 심함" + "오늘" 시작 → 오늘 바로 진료(응급실 고려)
   - 배 + 아주 심함 + 열 → 응급실
2. **2곳 이상 고르면 "이 중에 가장 불편한 곳은 어디예요?"를 한 번만 더 묻는다.** 의사가 진료할 때 주 증상을 먼저 묻는 것과 같다. 요약 문장과 의사 화면에서 주 증상을 맨 앞에 둔다.
3. **진료과는 부위 묶음으로 정한다.**
   - 고른 부위가 모두 같은 묶음이면 그 과. 예: 목·어깨 + 허리·등 + 팔·손 + 다리·발은 근골격 묶음 → 정형외과(저림이 같이 있으면 신경과도 함께 보여준다).
   - 서로 다른 묶음이 섞이면 → 먼저 전체를 보는 가정의학과·내과를 1순위로, 가장 불편한 곳의 전문과를 2순위로 보여준다. 예: 머리 + 어깨 + 다리 → 가정의학과(1순위), 가장 불편한 곳이 머리면 신경과(2순위).
   - 온몸 + 열 → 내과·가정의학과.
4. **추천 이유를 한 줄로 보여준다.** 예: "여러 곳이 함께 아파서, 먼저 전체를 보는 가정의학과를 추천해요."
5. 이 규칙은 검증된 확률이 아니다. ⑤(의사 확인 라벨)가 쌓이면 실제로 맞았는지 측정해서 고친다.
| 2 | 의사 사전 문진 카드 — 대기열에서 환자를 누르면 문진 요약(A2) 표시. 의사 거부감을 줄이는 원칙(아래) 적용 | 완료 |
| 3 | 진료 완료 처리 — 소견·처방·진료비 입력 → 방문을 수납대기로, 환자 수납 화면과 연결 | 대기 |

## 회차 기록

### 1회차 — 오늘 진료 대기열
- `src/doctor/queue.ts`: `localDateKey()`(로컬 날짜), `todayQueue()`(오늘·예약만, 시각 순, 시각 없는 건 뒤로).
- `Visit.time?`(HH:MM) 추가. 예약 화면이 예약 시각을 저장한다. 예전 데이터는 시각이 없어도 그대로 읽힌다.
- `src/doctor/QueuePanel.tsx`: 대기 인원, 시각·이름·진료과·사유, 빈 상태, 같은 기기 시연 고지.

### 2회차(A1) — 대화형 문진 엔진 + 대화 화면
- `src/intake/engine.ts`: 부위(11곳) → 부위별 느낌(비유 설명 10가지, "잘 모르겠어요" 포함) → 시작 시점 → 아픈 정도(4단계) → 심해지는 때 → 동반 증상. `currentQuestion`·`answer`·`undo`·`summarize`·`guessParts`·`withJosa`.
- `guessParts`: 적어둔 문장에서 부위를 미리 고른다. "다리도 근데 좀 아프네", "어깨가 왜 뻐근하지"처럼 말이 끼어도 찾는다(기존 키워드 매칭이 놓치던 사례). "발"은 "발열"과 겹쳐 조사 붙은 형태로만 찾는다.
- `summarize`: 병명 없이 고른 답만 문장으로. 받침에 맞춰 이/가·은/는을 붙인다.
- `src/intake/IntakeChat.tsx`: 대화 기록(role=log), 한 질문씩, 누르는 답(44px 이상), 여러 개 고르는 질문은 "다음", "없음"류는 다른 선택을 푼다, 이전 질문으로, 진단이 아님 고지.
- 예약 화면 증상 단계에 연결: 정리된 문장을 환자에게 먼저 보여주고 예약 사유로 저장한다. "다시 정리하기"로 되돌릴 수 있다.
- 남은 점: 추천 진료과는 아직 문장 키워드 기준이다(A3에서 고른 부위 기준으로 바꾼다). 문진 답은 문장으로만 저장된다(A2에서 구조화 저장).

### 3회차(A2) — 문진 기록 구조화 저장
- `IntakeRecord`(engine): 부위·부위별 느낌·시작 시점·아픈 정도·심해지는 때·동반 증상·요약 문장·덧붙인 말·확인 시각. "없음"도 남긴다(없다고 답한 증상도 의사에게 정보다).
- `Visit.intake?` 추가. 저장소가 읽을 때 문진 기록 형태를 검사하고, 깨졌으면 방문은 살리고 문진 기록만 뺀다.
- 예약 화면 확인 카드에 "의사에게 더 전하고 싶은 말 (선택)" 입력(최대 300자). 예약하면 문진 기록이 방문에 함께 저장된다.
- 브라우저 확인: "배가 아파요"로 문진 → 덧붙인 말 입력 → 예약하면 저장소에 항목별 기록이 들어간다. 콘솔 에러 0.
- 눈에 띈 점: 같은 예시에서 추천 진료과가 문장 키워드 때문에 "외과·소화기내과"로 나온다. A3에서 고른 부위 기준으로 바꾼다.

### 4회차(A3) — 여러 증상 동시 처리
- engine: 2곳 이상 고르면 "이 중에 가장 불편한 곳은 어디예요?"(primary). 느낌 질문과 요약 문장이 가장 불편한 곳부터. 요약에 "가장 불편한 곳은 ○○예요." 한 문장. 문진 기록에 `primary` 저장(한 곳이면 그곳).
- `src/intake/triage.ts`: `checkRedFlags`(가슴+숨참/팔·어깨/아주 심함 → 119, 머리+저림 → 119, 머리+목·어깨+열 → 응급실, 배+아주 심함+열 → 응급실, 오늘 시작+아주 심함 → 오늘 진료; 겹치면 가장 급한 것). 문구에 병명 없음(테스트로 고정). `recommendDepts`(뼈·근육 묶음 → 정형외과·저림이면 신경과, 섞이면 가정의학과 1순위 + 가장 불편한 곳의 과 2순위, 온몸+열 → 내과·가정의학과, 두통 단독 → 가정의학과·신경과) + 이유 한 줄.
- 예약 화면: 문진을 마치면 키워드 대신 이 규칙으로 추천하고 이유를 보여준다. 위험 조합이면 경고(role=alert)와 "119에 전화하기"(tel:119)를 먼저 띄운다. 예약은 막지 않는다.
- 기존 테스트 변경과 이유: engine 테스트 3개·IntakeChat 테스트 1개가 2곳 이상을 고르는데, 흐름에 "가장 불편한 곳" 질문이 새로 들어가서 그 답을 끼워 넣었다. 요약 기대값에 "가장 불편한 곳은 ○○예요." 문장이 추가됐다. buildRecord 기대값에 `primary`가 추가됐다. 검사 내용을 약하게 바꾼 것은 없다.
- 브라우저 확인: "머리가 아프고 다리도 근데 좀 아프네 그리고 어깨가 왜 뻐근하지" → 가장 불편한 곳 질문 → "여러 곳이 함께 아파서…" + 가정의학과·신경과. "가슴이 아파요" + 숨이 참 → 119 경고. 콘솔 에러 0.

### 번외 — 서울 병원 목록(공공데이터) · 아이콘 교체
- 사용자 요청 "서울 병원 거의 다". 크롤링 대신 심평원 공공데이터(공공데이터포털 15051059, 2026-09-30 기준, 공공누리 제1유형)를 받아 썼다. 서울 19,929곳(의원 10,728 · 치과의원 4,889 · 한의원 3,721 · 병원 231 · 요양병원 101 · 종합병원 45 · 상급종합 14 등), 약국·조산원 제외.
- `scripts/build-hospitals.mjs`: CSV(cp949) → `public/data/hospitals/seoul/<구>.json` 25개(총 6.9MB, 구당 수십~수백 KB) + `src/booking/hospitals.seoul-index.json`(구 목록·건수, 상급종합 14곳, 출처·기준일). 법인명 접두어를 뗀 `shortName`. 서비스워커 precache에는 json이 없어 미리 받지 않는다.
- `src/booking/hospitals.ts`: `matchesDept`(소화기내과 → 내과 별칭), `filterHospitals`(진료과 + 이름·동 검색, 띄어쓰기 무시), `loadGuHospitals`(구별 1회 fetch, 실패 시 오류).
- `src/booking/HospitalPicker.tsx`: 상급종합 14곳 바로 선택, 구 선택(기억), 검색, 30개씩 더 보기, 로딩·오류(다시 시도)·빈 상태, 출처 표기. 저장되는 이름은 공식 요양기관명.
- 예약 화면의 데모 병원 4곳(분당서울대병원 포함, 서울 아님) 제거. 기존 테스트는 상급종합 목록의 "서울대학교병원"을 그대로 눌러 통과.
- 브라우저 확인: 가정의학과 → 강남구 494곳, 삼성서울병원·강남세브란스병원이 맨 위. 
- 아이콘: 말풍선 + 맥박선으로 교체(icon.svg, 192/512 png, maskable, apple-touch). 앱 안 로고(로딩·온보딩)도 `BrandMark`로 통일.

### 6회차(D1) — 병원 시연 모드
- `src/doctor/demo.ts`: 오늘 날짜 시연 환자 4명(박영희 머리+목·어깨 / 이준호 배·구토 / 최민서 허리+다리·저림 / 김복순 가슴+숨참 → 응급 안내). 문진 답을 실제 엔진으로 돌려 요약·진료과를 만들고, 고정 id(`demo-N`)라 두 번 불러도 중복 없음. "시연 환자 지우기"로 그것만 제거.
- `Visit.patientName?`(회원 아닌 환자 표시 이름) 추가·검증. `addVisit`이 id를 받으면 그대로 쓰고 같은 id는 덮어씀. `removeVisitsByIdPrefix`.
- 대기열: 시연 환자에 "시연" 배지, 하단 버튼 토글(불러오기/지우기), 다른 기기에서 보여줄 때의 안내 문구.

### 5회차(②) — 의사 사전 문진 카드
- `src/doctor/intakeView.ts`: 저장된 문진 기록 → 의사 카드 항목(가장 불편한 곳, 부위별 느낌과 비유, 시작, "5/10 · 일상이 불편한 정도", 심해지는 때, 동반 증상, 없다고 답한 증상, 환자가 쓴 말). 해석·추정은 더하지 않는다.
- engine에 표시용 조회 추가: `qualityInfo`·`onsetLabel`·`severityInfo`·`ASKED_ASSOCIATED`.
- `src/doctor/IntakeCard.tsx`: 의사 화면 원칙대로 — 환자 답 그대로, "환자가 받은 안내: ○○ (규칙 기반 진료과 안내, 진단 아님)"는 맨 아래 작게, 환자 화면에 위험 안내가 떴으면 맨 위에 알림. 문진 없이 예약한 환자는 그렇다고 알리고 예약 사유만.
- 대기열 항목마다 "문진" 버튼(aria-expanded)으로 카드 열고 닫기.
- 브라우저 확인: 환자 화면에서 문진 + 덧붙인 말 + 예약 → 의사 대기열에서 문진 카드에 항목별로 표시. 콘솔 에러 0.
